# 双端链路实测 2026年9月13日

探针 69400240 对应遥控端，20090928 对应车载端。双端均识别到 Cortex-M0，Flash 向量与各自产物一致，诊断 magic 为 0x52455344、revision 为 0x20260912。两端主循环计时持续增长，PC 分别位于 0x080025B2 和 0x080020EC；遥控端本次已运行用户程序。

## 观察结果

每端连续观察约8秒，未重刷或修改安全输入。

| 诊断量 | 遥控端 | 车载端 |
|---|---|---|
| 串口成功发送帧数 | 907 → 937 | 1 → 1 |
| 接收字节数 | 58 → 58 | 133 → 133 |
| UART错误计数 | 0 → 0 | 6 → 6 |
| 有效ACK | 0 | 不适用 |
| 状态 | STOP_LATCHED=2 | STOPPED_FAULT=4 |
| 故障位 | 0x0B 电量无效/低/临界 | 0xC2 遥控STOP/CAN故障/锁定 |
| 输出命令 | 0x0A 红黄亮，蓝绿灭 | 0 两路安全继电器释放 |

遥控端 PB1 实测读回为高，对应急停/断线故障。电量测量无效，INA226 last_error=2（IO_ERROR），错误计数2262→2339。不能把电压字段0解释为电池真的0V。

GPIOB ODR 遥控端0x1400：PB10蓝和PB12绿为高，PB11黄和PB13红为低，与低电平触发灯态相符。车载端 ODR 0x2C00，PB10/PB11均高，符合继电器释放命令。命令及GPIO读回不能证明机械触点实际状态。

## 无线证据

遥控端58字节轨迹包含 `Start PingPong`、`Please push button1 or button2`；车载端轨迹包含相同演示文字及 `Receive Data:` 后的 RS 二进制数据。文件：tmp/remote_trace_20260913.bin、tmp/vehicle_trace_20260913.bin。

因此模块串口当前输出演示协议文字，并非预期纯二进制RES桥。结合车载端REMOTE_STOP和一次ACK，可判断曾解析到STOP，但当前没有持续收发或反向有效ACK。STM32 HAL发送成功只证明MCU UART传输完成，不能证明RF已经发射。

仓库自定义STM8桥无上述演示输出。必须核对两块无线板实际固件并通过其STM8 SWIM接口更新；当前两根STM32 J-Link SWD连接不能直接烧录无线板STM8。当前证据不能区分无线桥串口缓存、RF设置及接收模式问题各自的贡献。

## 纠正与后续

此前认为自定义桥一定等待500ms并不准确：SDK提供约10ms帧结束标志和500ms兜底标志，自定义main同时检查两者。是否满足总链路时序仍需要实际桥固件与时基验证，不能仅凭500常量下结论。

此前仅凭Flash内容一致就认定物理目标仍为车载端也不充分：Flash只能识别已安装固件，不能单独证明线接在哪块板。本次结合用户布置、role和运行行为确定测试对应关系。

当前STOP输出符合输入故障；不能强制READY掩盖PB1和INA226问题。先恢复无线板透明协议收发、PB1健康回路和INA226通信，再验证READY、单次GO、按急停停止心跳、断链500ms释放以及外部人工锁存复位。现有7项主机回归通过，未等同于上述完整实机验收。
