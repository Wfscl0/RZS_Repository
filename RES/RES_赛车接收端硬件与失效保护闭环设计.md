# RES赛车接收端固定硬件条件下的失效保护设计

版本：2026-07-30

## 1. 固定硬件拓扑

赛车接收端不增加独立硬件失效保护板，也不安装INA226。接收器主体固定为：

```text
赛车12 V -> DCDC -> STM32G0B1
                         ├─ UART -> E220/LoRa模块
                         ├─ FDCAN -> CAN收发模块 -> VCU/记录仪
                         └─ GPIO -> 失电释放式接收端继电器 -> SDC
```

其中继电器不能省略。2026规则要求赛车接收端至少有一个继电器直接串入SDC。继电器模块是RES的安全输出执行器，不是额外的“硬件失效保护板”。

赛车现有的IMD/BMS/EBS/RES非可编程错误锁存板继续作为整车安全系统的一部分，不集成在RES接收器内部。

## 2. CAN和无线的分工

- LoRa链路负责接收遥控端的认证心跳、STOP及Go请求。
- CAN负责把Go请求、链路状态、遥控STOP、接收器故障和计数器发送给VCU/数据记录仪。
- Go只通过CAN作为请求交给VCU；VCU仍需自行检查全部AS Ready条件。
- STOP不依赖CAN：接收器GPIO直接撤销继电器驱动，继电器常开触点断开SDC。
- CAN开路、短路、Bus-off或VCU掉电不得阻止继电器释放；CAN故障至少应禁止新的Go。

## 3. 最小安全输出结构

### 3.1 接收端继电器

采用“高电平允许、失电释放”的继电器驱动：

```text
STM32 RELAY_EN=1 -> 驱动管导通 -> K_RES线圈吸合 -> K_RES_NO闭合
STM32复位/掉电/RELAY_EN=0 -> K_RES释放 -> K_RES_NO断开SDC
```

要求：

1. 必须使用常开触点；
2. GPIO与驱动输入之间设置外部下拉，使STM32复位高阻时继电器保持释放；
3. 不使用“低电平触发且上电可能吸合”的通用继电器模块；
4. 继电器触点DC额定能力不低于规则要求，并按实际SDC电流留余量；
5. 优先使用双转换触点继电器：第一组NO直接串入SDC，第二组触点反馈真实机械状态；
6. 线圈必须有续流钳位，驱动管失效模式及释放时间需要实测。

推荐仍可使用`OMRON G7SA-2A2B DC12`，但在本方案中它只是接收端继电器，不构成另一块保护板。若成本或体积不允许，可选额定值合适的12 V双转换继电器，但普通继电器的反馈触点不具备强制导向保证，ASF中不能写成“安全继电器反馈诊断”。

### 3.2 SDC及手动模式

建议整车接法：

```text
SDC_IN -> 现有错误锁存板K_LATCH_NO
       -> [ K_RES_NO || K_AS_BYPASS_NC ]
       -> SDC_OUT
```

- K_RES_NO：RES接收器常开触点，无人驾驶模式下直接控制SDC。
- K_AS_BYPASS_NC：由ASMS直接驱动的强制导向继电器常闭触点，手动模式旁路RES。
- K_AS_BYPASS的NO触点同时控制AS供电，使“RES被旁路”和“AS获得供电”不能同时出现。
- 该旁路必须是赛车原有硬件逻辑，不能由CAN或VCU软件完成。

## 4. 固定硬件下的失效保护链

### 4.1 上电和复位

- `RELAY_EN`上电默认为低，外部下拉建议10 kΩ～47 kΩ；
- STM32完成时钟、RAM关键区、GPIO、无线协议和继电器释放反馈检查前，不允许置高`RELAY_EN`；
- 启用最高可用BOR等级，使3.3 V下降时尽早复位；
- 启用独立IWDG，建议初始超时250～400 ms；IWDG只能在完整主循环健康路径中喂狗，禁止在定时器中断中无条件喂狗；
- 看门狗复位后重新进入STOP，不能从RAM、Flash或备份寄存器恢复继电器允许状态。

### 4.2 无线超时

- 遥控端心跳周期200 ms；
- 车辆端只有CRC、SipHash认证、会话号、序号和信道检查全部通过的报文才能更新`last_valid_packet_ms`；
- 从最后一个有效认证报文起500 ms未收到新报文，立即清零`RELAY_EN`并置位`RES_FAULT_LATCHED`；
- 收到STOP报文不等待500 ms，立即清零`RELAY_EN`；
- CRC错误、认证失败和重放包不能刷新超时计时器；
- E220 UART收到任意字节、无效帧或旧帧也不能刷新超时。

### 4.3 软件锁存和整车硬件锁存

车辆端软件设置`RES_FAULT_LATCHED`，以下任一条件置位：

- 遥控STOP；
- 500 ms无线超时；
- 会话异常或连续认证失败；
- 继电器命令与反馈不一致；
- CAN初始化失败/Bus-off时至少禁止Go；
- 看门狗、BOR或其他异常复位（重新启动后默认视为已锁存故障）。

软件锁存只用于防止程序自动重新吸合K_RES，不能替代规则要求的非可编程锁存。K_RES释放时，物理辅助触点或失电安全的`RES_HEALTHY`信号必须让赛车现有错误锁存板锁存并断开其串联触点。无线恢复、CAN恢复和STM32复位均不得自动清除整车锁存。

现有锁存板的`R_E_RESET`必须取消VCU软件控制，只允许车外人工按钮或LVMS重新上电复位。

## 5. 无额外硬件板时的接口实现

如果使用双转换继电器：

| 触点 | 连接 |
|---|---|
| NO1 | 直接串入SDC |
| COM1 | SDC线路 |
| NO2 | 接受监控的5 V，触点闭合后输出`RES_HEALTHY` |
| COM2 | 送现有错误锁存板RES输入 |

错误锁存板RES输入应设置下拉，使接收器掉电、继电器释放或反馈线断开均表现为低电平故障。这样不需要增加保护板，只需利用继电器第二组触点和现有锁存板。

如果现有继电器模块只有一组触点，则只能实现SDC断开，无法从物理触点形成闭环反馈。可以投入原型通信测试，但不能在ASF中声称已经完成继电器反馈诊断。

## 6. STM32G0B1引脚建议

| STM32引脚 | 功能 | 安全默认状态 |
|---|---|---|
| PA9 | USART1_TX -> E220 RXD | AF |
| PA10 | USART1_RX <- E220 TXD | AF |
| PB8 | FDCAN1_RX <- CAN RXD | AF |
| PB9 | FDCAN1_TX -> CAN TXD | AF |
| PB10 | `KRES_RELAY_EN` | 输出低，外部下拉 |
| PA8 | `KRES_NO_FB` | 输入，下拉；可选物理反馈 |
| PB0 | `AS_MODE_HW` | 输入；来自ASMS硬件触点/光耦 |
| PB1 | `RES_RESET_SENSE` | 输入；只读取人工复位，不得输出复位 |
| PB12 | `CAN_STB` | 外部上拉，复位时CAN静默 |
| PB13 | 状态LED/诊断 | 可选 |
| PA13/PA14 | SWDIO/SWCLK | 保留调试 |

PB8/PB9用于FDCAN1。移除INA226后PB6/PB7和I2C1可释放备用，但没有必要为了CAN改用这两个引脚。

## 7. CAN收发模块要求

CAN不是安全执行通道，但仍建议使用支持3.3 V逻辑接口、掉电总线高阻及总线故障保护的收发器。推荐`TCAN1042HGV-Q1`：

- VCC接5 V；
- VIO接3.3 V；
- STB外部上拉，使STM32复位时CAN保持静默；
- CANH/CANL增加CAN专用TVS；
- 120 Ω终端通过跳帽选择，只在物理总线末端接入；
- CANH/CANL采用双绞线，支线尽可能短。

若采用现成CAN模块，必须核对其逻辑电平、默认STB状态、是否自带120 Ω电阻以及是否把5 V直接送到STM32 RX脚。不能只根据商品标题判断兼容。

## 8. 固件安全状态机

```text
BOOT/RESET
   -> 强制RELAY_EN=0
   -> 初始化IWDG、UART、FDCAN
   -> 检查继电器处于释放状态
   -> WAIT_AUTHENTICATED_LINK

WAIT_AUTHENTICATED_LINK
   -> 连续收到有效认证帧且遥控STOP已释放
   -> 等待赛车端人工清除整车硬件锁存
   -> SAFE_MONITOR

SAFE_MONITOR
   -> RELAY_EN=1
   -> 每帧执行认证/序号检查
   -> 新Go边沿通过CAN报告VCU
   -> STOP/500ms超时/复位/反馈异常 -> FAULT_LATCHED

FAULT_LATCHED
   -> RELAY_EN=0
   -> 上报故障
   -> 软件不自行退出
   -> 需要人工复位整车锁存并重新建立有效无线会话
```

## 9. 能覆盖和不能覆盖的故障

| 故障 | 当前固定硬件能否安全处理 |
|---|---|
| 遥控端掉电、无线遮挡、LoRa模块失联 | 能，500 ms软件超时释放继电器 |
| 赛车接收端12 V或DCDC掉电 | 能，继电器失电释放 |
| STM32正常复位/BOR/IWDG复位 | 能，GPIO高阻及下拉释放继电器 |
| UART断线或持续无效报文 | 能，不刷新有效帧时间 |
| CAN故障 | 能保持硬线STOP功能；禁止新的Go |
| 继电器线圈断路或反馈线断路 | 双触点反馈方案可检测并进入现有锁存板 |
| STM32程序错误地持续喂IWDG并保持RELAY_EN高 | **不能完全覆盖** |
| GPIO或驱动管危险性短路导致继电器持续吸合 | **不能完全覆盖** |
| 单组普通继电器主触点焊死 | **不能由同一继电器自行覆盖**，依赖整车锁存板串联触点作为第二断开通道 |

后三类故障只有增加独立硬件监控、独立第二通道或安全控制器才能完全覆盖。既然硬件已固定，ASF中应准确写成“IWDG/BOR、失电释放及整车非可编程锁存”，不能写“独立硬件无线超时”或“单故障完全容错”。

## 10. 验证要求

1. 实测最后一个有效认证报文到K_RES主触点断开的时间，目标不超过700 ms；
2. 遥控端断电、接收端断电、拔天线、金属罩屏蔽；
3. UART开路、RX持续乱码、重放包及错误认证包；
4. STM32按NRST、停在断点、主循环死锁并确认IWDG复位；
5. 12 V和3.3 V缓慢下降、棕断及快速反复上电；
6. CAN开路、短路和Bus-off，确认硬线STOP不受影响；
7. 继电器线圈断路、反馈线断路；
8. 故障恢复后确认SDC不会自动闭合，必须人工复位；
9. 连续重复至少100次STOP/恢复循环；
10. 手动模式验证ASMS硬件旁路，且ASMS打开后RES能够控制SDC。
