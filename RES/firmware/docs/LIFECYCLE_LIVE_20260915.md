# 2026-09-15 RES 实机生命周期调试

用户最终确认仅 RES 两端在环，未连接车辆执行回路。

## 已测证据

- 两个 J-Link 均可连接，MCU 主循环计时增长。
- LoRa USB 串口现为 COM6/COM7，9600 8N1 被动监听 8 秒均无数据。
- 遥控 TX 在 8 秒内从 569 增至 600，RX 为 0，已接受 ACK 为 0。
- 车载 RX/TX 均为 0，WAIT_LINK，继电器命令位 1。
- 车载 GPIOB ODR/IDR 均为 0x2800：PB10 低，PB11 高；符合待机 R1 闭合/R2 释放驱动要求，但尚无触点测量。
- 两端 USART1 CR1=0x2D，CR2=0，CR3=1，BRR=0x1A0B；PA9/PA10 为 AF1，USART1 中断已启用。配置与当前 9600 8N1 设计一致。
- 遥控电量无效，故障 0x0B，STOP_LATCHED；PB1 急停输入本次为健康，不能把此 STOP 归因于急停按钮按下。车载 CAN 故障位 0x40。

## 当前结论

上电待机输出已确认。无线建链、READY、GO、急停空口时延、断链恢复尚未实机通过。先前 ASCII 双向 USB 测试成功仅说明当时低频发送可通信，不能证明当前 RES 负载下闭环可靠。先前“反向必为遥控 PA10 接线故障”结论过强：车载 UART TX 完成不能证明 ACK 已到空口，半双工碰撞、模块模式和输出路径仍待区分。

目前 USB 与 MCU 串口同时接入，需避免 CH340 TX 与 STM32 TX 并联驱动。下一步采用两块模块独立 USB 测试，先断开 MCU—LoRa TX/RX，再逐向发送并抓取完整数据；随后逐条接回 MCU UART 进行定位。

生命周期结论保持“部分完成”。8 项主机测试通过不能替代完整 ASF 失效模式实测，也不能证明继电器物理反馈、硬件锁存或 VCU 超时已经验收。

## 独立 USB 测试及模块复位

用户确认两端 MCU—LoRa TX/RX 已断开后，COM6→COM7 和反向各发送 ASCII，等待 4 秒均无输出。随后保持串口监听，用户按两块 LoRa 复位键：两端均输出 Start PingPong 启动信息（COM6 出现两次，不能据此认定异常自动复位）。

复位后交替执行三轮双向测试，完整唯一载荷匹配 6/6 成功：COM6→COM7 为 508/494/497 ms；COM7→COM6 为 510/527/495 ms。确认本次模块复位后恢复了低频 ASCII 双向收发；之前无响应的根因仍未确定，不能断言模块损坏或仅接线错误。

实测单向延迟已高于正式 STM32 程序的 260 ms ACK 接受窗口，提示演示固件时序与 RES 正式闭环不匹配。该时延只适用于此次测试长度和条件，不是 RES 帧的精确往返时延。尚需验证二进制帧完整性、收发调度及模块桥接固件，不能通过放宽车载安全超时来宣称解决。
