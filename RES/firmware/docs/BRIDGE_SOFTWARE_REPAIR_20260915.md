## 已完成

修改两块LoRa板共用的STM8桥接源码，并同步至E220_IAR_SDK的IAR工程：

1. 串口中断写入128字节环形队列（可用127字节），主循环逐字节组帧，按长度和CRC检查后立即发送完整帧。不再等待演示FIFO的500 tick超时，不再把连续两帧作为一个报文拒收。
2. 遇到非法头、非法长度、CRC错误时滑动重同步；溢出时放弃有缺口的缓存并重新组帧。增加桥接溢出、错误帧和发送调用计数。发送计数不是远端收到数据的证明。
3. 收到无线有效帧后，先切换到下一监听信道，再通过UART通知STM32，以缩短回复前的监听空窗；无效帧不输出，重新扫描。
4. 修正E220底层驱动在接收回调后SetRx(0)覆盖扫描超时的问题。
5. 新增bridge_stream_framing测试：半帧、连续74字节双帧、CRC错误后恢复、61字节最大帧、溢出恢复、接收后监听及超时重启。

## 剩余问题

- USB CH340 TX与STM32 TX同网的电气冲突，软件组帧不能消除。须通过实测验证当前板版及连接条件，不承诺本修复可独立解决全部链路问题。
- 当前遥控PB1为故障输入，INA226测量无效，仍应保持STOP。恢复无线不能等同于允许进入READY。
- 双端桥固件必须配套部署（当前配置含相同跳频表与空中速率），不能一端演示固件、一端新桥即宣称可兼容。
- 下一验收顺序：双向完整帧与认证ACK计数、最大往返时延、连续运行丢包、STOP/断链/恢复行为。任何一次源码测试都不能替代这些实机测量。
