# RES 遥控端重启恢复逻辑

用户确认：图中“拔起急停、重启电源”指遥控端电源；车载端保持供电。本轮仅修改软件、运行主机测试及构建车载映像，没有烧录或操作实物继电器。

## 工作流程

1. 车载端正常启动、没有本地故障：R1 闭合，R2 断开，等待通信。复位/初始化期间仍均释放。
2. 遥控端健康、有效通信建立并连续通过三次 READY：R1/R2 均闭合。
3. 操作者按启动按钮：输出一次 CAN GO 和约 100 ms 的 START 脉冲。按钮长按、重发不重复启动。
4. 急停或 500 ms 通信超时：R1/R2 均断开，立即撤销 START。遥控端停止普通心跳并报告 STOP。
5. 只拔起急停或只恢复同一会话通信：不能重新获得许可。
6. 拔起急停、关闭并重新开启遥控端：车载收到不同的新会话 HELLO，开始恢复确认，两路仍保持断开。
7. 本地故障已消失，连续三次有效 READY 后恢复两路继电器许可。不重启车载端，不自动输出 GO；必须重新按启动按钮。

恢复期间再次出现 STOP、超时或本地故障，会取消本轮恢复，重新要求遥控端重启。急停未释放就重启遥控端，不能获得 READY。

RES 允许恢复不等于整车 SDC 已恢复。独立非可编程锁存板仍按 ASF 由外部人工复位/LVMS 复位，软件没有操作或清除该硬件锁存的接口。

## 实现及兼容性

- 车载应用增加新会话恢复候选状态，仅第三次有效 READY 清除 RES 停止保持状态。
- 保留内部 `fault_latched` 和 CAN bit7 的既有接口名称，含义为“RES 停止保持、尚未完成遥控重启恢复”，不是不可恢复的永久锁存，更不是外部硬件锁存状态。
- 新会话切换先撤销继电器/START；旧 READY、GO 计数、历史会话不能直接恢复运行。
- 遥控端原有“急停保持到遥控端重启”的行为无需修改。本轮只生成新的车载端映像，兼容当前遥控端诊断版。
- CAN、无线初始化和其他本地故障仍有优先级。`local_fault_flags` 必须由本地驱动确认解除，不能由遥控报文擦除。本轮未修改 CAN/无线驱动故障恢复，当前 error=8 仍需单独定位。

## 测试

11/11 项主机测试通过，GNU 车载构建通过。新增/调整覆盖：

- 急停后同会话 READY 不恢复；新会话经过三次 READY 恢复。
- 恢复前两个 READY 两路仍断开；恢复不产生额外 GO。
- 超时后只重启遥控应用即可恢复，车载应用实例及会话不变。
- 重新按 GO 才增加启动计数；重复或旧 GO 计数不触发。
- 本地故障未清除、新会话重启仍不能恢复。
- 恢复中 STOP、超时撤销候选。
- 已观察到的旧会话被拒绝。

双端联动测试使用模拟有效电量与 CAN；不能视为现场外围已经正常。

## 当前限制

会话识别沿用现有协议，不能从无线报文物理证明操作者真的断电。遥控 boot session 仍由 UID/启动时序混合生成，不是持久化单调计数或完整随机挑战协议；若重启得到同一会话号，将安全拒绝恢复。正式部署前仍应完善会话新鲜性和专用密钥。

为避免循环使用旧会话，车载在本次供电期间最多记录 32 个会话，满后拒绝新增会话，不淘汰历史来放行；达到该限制需在安全条件下重启车载。该保护只覆盖已观察到的会话，不构成跨车载断电的完整防重放证明。
